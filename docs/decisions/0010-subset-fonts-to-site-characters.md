# 0010. Subset the fonts to the characters the site uses

Date: 2026-11-05  
Status: accepted

## Context

[0009](0009-self-hosted-font-files.md) committed the Fontsource Latin and Latin Extended `woff2` files. Measured on the milestone 3 preview ([Lighthouse report](../audits/2026-11-05/lighthouse-landing.md)), a page loaded 8 to 12 of those files: 111 KB on `/` and 156 KB on `/cs/`, above the 150 KB target. The name “Křapka” alone pulls in the Latin Extended file of every face, and Space Mono, used only for small labels, was the heaviest family (about 16 KB per file). With Lighthouse's slow-phone simulation, the final text paint waits for the fonts, so fonts were the main part of a Largest Contentful Paint of 2.0 to 2.1 s against a 2.0 s target.

## Decision

Build one small `woff2` per family and weight that contains only the characters the site can show: printable ASCII, the full Czech alphabet, typographic punctuation, and every other non-ASCII character that appears in `src/`. The files are generated by `scripts/subset-fonts.py` from the unmodified Fontsource files and committed as `<family>-site-<weight>-normal.woff2` in `src/assets/fonts/`. With one file per weight, the Latin / Latin Extended `unicode-range` split in `astro.config.mjs` is no longer needed and was removed. A character outside the files falls back to the next font in the stack, as before for arrows, which these fonts never contained.

Result: 6 files, 56.6 KB on every page (was 111 KB on `/` and 156 KB on `/cs/`). Local Lighthouse (same machine, simulated slow phone): LCP 1.7 s to 1.4 s, Performance 99 to 100.

The fonts are modified, which SIL OFL 1.1 allows. None of the three licences declares a Reserved Font Name, and the licence files keep shipping with the site (LEG-008).

## Alternatives considered

- **Drop Space Mono 400 and use the bold weight for all mono text.** Would remove one file; with the subset files it now saves about 6 KB (about 32 KB before subsetting). Cost: the contact link line and the screenshot tag become bold. Not done; the budget is met without it.
- **Merge Sora 600 and 700 into one weight.** Would save about 11 KB (about 22 KB before subsetting). Cost: navigation, sublines and buttons share one weight, a visible change to the typography. Not done.
- **A variable Sora file.** One file would cover 400 to 700, but it means a new download from Fontsource and a new file format to maintain. Not tried.
- **Keep the split Latin / Latin Extended files and only drop weights.** Smaller win, and a visible design change.

Options 1 and 2 are the next levers if the font payload or LCP needs to shrink further. Together they would save roughly 17 KB.

## Consequences

- Fonts are about a third of the previous size, and the 150 KB budget has plenty of room (56.6 KB).
- A new character in the copy (for example Polish letters, or a new symbol) cannot slip through: `scripts/check-fonts.mjs` (`pnpm check:fonts`, part of `pnpm verify` and the CI job `check`) fails the build when a built page shows a character missing from `src/assets/fonts/charset.json`, checking lower and upper case. The fix is to re-run `scripts/subset-fonts.py`, which rebuilds the set from `src/` and the manifest, and commit both. Checked on 5 November 2026 by adding “ő ł” to a heading: the check failed naming the four characters, regenerating fixed it.
- Regenerating needs the original Fontsource files (see [src/assets/fonts/README.md](../../src/assets/fonts/README.md)) and a throwaway Python environment with `fonttools` and `brotli`.
- Revisit when the design adds a language or a new typeface.
